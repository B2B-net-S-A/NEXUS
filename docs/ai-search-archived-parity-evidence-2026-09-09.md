# Archived full-search comparison

A01 acceptance requires the same request, actor, versions and candidate data to produce the same base fit and ordering. UI rounding is insufficient proof: C2 displays whole points while Radar exposes a decimal value.

The fixed diagnostic operation (`action=candidate-index-audit`, `candidate_search_diagnostics=true`) now also compares up to three pairs from its ten most recent finished runs, paired by actor and request fingerprint. It reads archived result columns and emits aggregates only: population identity, changed candidate versions, eligibility differences, comparable measured pairs, maximum score difference, differences above 0.1 points, full ordering equality and ranking completeness. No candidate IDs, actor IDs, CVs or request text are exported; no provider calls or database writes are added by the comparison.

Matching scores among measured rows are not full ranking parity. `archived_parity_complete` requires two distinct runs, identical actor/request/version context, the same complete population and candidate versions, equal eligibility and order, complete measured rankings and no score difference above 0.1. Missing/invalid measurements, partial runs, changed facts and omitted/duplicate snapshot rows cannot establish parity. Empty measured subsets report a null maximum difference rather than zero.

This report proves properties of stored default-filter snapshots. The operator must link run IDs to the actual Radar/C2 interactions; it does not independently identify the initiating screen, prove live freshness, validate recruiter relevance or complete index reconciliation. Frozen human quality judgments remain a separate acceptance requirement.

Validation: 45 unique focused native comparison, runtime diagnostic and operational transport tests passed across the targeted runs. This includes the real SQLAlchemy snapshot query against a small native SQLite fixture with an unrelated run, plus exact scores, stable ties, partial indexing, changed versions/context, invalid numbers, distinct-run rejection and actor-scoped bounded pair selection. Closed transport projection discards candidate/source fields and rejects nonfinite metrics and more than three comparisons. Production execution remains pending delivery of this follow-up in PR #1452.
