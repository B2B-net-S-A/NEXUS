LIKELY FIX (for orchestrator to consider)
The compose file likely has explicit `ports: ["8000:8000"]` (and possibly "3000:3000",
"5432:5432", "6333:6333") which conflicts with Coolify's own port and exposes db/qdrant
publicly. With Coolify + Traefik, services should NOT publish ports to the host —
Traefik routes via the internal docker network using the domain bindings we just set
(api.nexus.dynaminds.pl -> backend:8000, nexus.dynaminds.pl -> frontend:3000).

Suggested compose change: remove `ports:` blocks from backend, frontend, postgres,
qdrant. Keep only `expose:` (or nothing) — Coolify auto-derives expose from domain
config. After patching, redeploy.

Note that Coolify can ALSO override the compose at runtime via "Show Deployable
Compose" (button visible on General page) — but the source-of-truth is the repo's
docker-compose.yml at /docker-compose.yml.
